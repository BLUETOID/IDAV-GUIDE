1. Mining Frequent Itemsets & Market Basket Analysis

Definition and the Market Basket Model

Frequent itemset mining is an unsupervised exploratory data mining technique designed to discover co-occurrence relationships and associations among items in large transaction datasets. Originally formulated by Agrawal, Imieliński, and Swami (1993) for retail market basket analysis, the model abstracts a general relationship between two sets of entities:

  • Items: A universe of distinct entities \(\mathcal{I} = \{i_1, i_2, \dots, i_m\}\) (e.g., supermarket products, web pages, medical symptoms).
  • Transactions: A database \(\mathcal{D} = \{T_1, T_2, \dots, T_n\}\), where each transaction \(T_j \subseteq \mathcal{I}\) is a subset of items purchased together, associated with a unique transaction identifier (TID).
  • Itemset: Any subset \(X \subseteq \mathcal{I}\). An itemset containing \(k\) items is termed a \(k\)-itemset.

Core Association Measures

An association rule is an implication expression of the form \(X \implies Y\), where \(X, Y \subset \mathcal{I}\) and \(X \cap Y = \emptyset\). Here, \(X\) is the antecedent (body) and \(Y\) is the consequent (head). The strength and interestingness of itemsets and rules are governed by mathematical metrics:

Measure Formula Interpretation
Support (Itemset) \(\text{supp}(X) = \frac{|\{T \in \mathcal{D} \mid X \subseteq T\}|}{|\mathcal{D}|}\) Fraction of total transactions in database \(\mathcal{D}\) that contain itemset \(X\). Measures statistical significance.
Support (Rule) \(\text{supp}(X \implies Y) = \text{supp}(X \cup Y)\) Fraction of transactions that contain both antecedent \(X\) and consequent \(Y\) simultaneously.
Confidence \(\text{conf}(X \implies Y) = \frac{\text{supp}(X \cup Y)}{\text{supp}(X)} = P(Y \mid X)\) Conditional probability that a transaction contains \(Y\) given that it contains \(X\). Measures reliability of the rule.
Lift \(\text{lift}(X \implies Y) = \frac{\text{conf}(X \implies Y)}{\text{supp}(Y)} = \frac{\text{supp}(X \cup Y)}{\text{supp}(X) \times \text{supp}(Y)}\) Ratio of observed joint support to expected support under statistical independence:
  • \(\text{lift} = 1\): \(X\) and \(Y\) are independent (no association).
  • \(\text{lift} > 1\): Positive association (\(X\) encourages purchase of \(Y\)).
  • \(\text{lift} < 1\): Negative association / substitute products.
Conviction \(\text{conv}(X \implies Y) = \frac{1 - \text{supp}(Y)}{1 - \text{conf}(X \implies Y)}\) Measures degree of implication dependency. A value of \(\infty\) indicates a logical implication with zero exceptions.
Leverage \(\text{lev}(X \implies Y) = \text{supp}(X \cup Y) - (\text{supp}(X) \times \text{supp}(Y))\) Difference between observed frequency and expected frequency under independence. Ranges from \([-0.25, 0.25]\).

2. The Apriori Algorithm

The Apriori Property (Anti-Monotonicity Principle)

The search space of candidate itemsets for a universe of \(m\) items is the power set \(\mathcal{P}(\mathcal{I})\), which contains \(2^m - 1\) non-empty itemsets. For a retail catalog with \(m = 10,000\) items, exhaustive counting is computationally impossible. The Apriori Algorithm makes this search tractable by exploiting the fundamental anti-monotonicity property of support:

The Apriori Principle (Anti-Monotone Property of Support) If an itemset \(X\) is frequent, then all of its non-empty subsets must also be frequent.
Contrapositive (Pruning Rule): If an itemset \(X\) is infrequent (\(\text{supp}(X) < \text{min\_sup}\)), then any of its supersets \(Y \supset X\) is guaranteed to be infrequent and can be pruned immediately without database counting.

Figure 1: Apriori lattice pruning. Because {D} is infrequent, all supersets involving D are pruned without counting. The candidate {A, B, C} is pruned prior to database scanning because its subset {B, C} is infrequent.

Step-by-Step Apriori Algorithm Workflow

  1. Pass 1: Scan database \(\mathcal{D}\) once to compute support counts of all 1-itemsets. Discard those with count \(< \text{min\_sup}\) to form the frequent 1-itemset list \(L_1\).
  2. Candidate Generation (\(L_{k-1} \bowtie L_{k-1}\)): Join two frequent \((k-1)\)-itemsets if they share the first \((k-2)\) items in common (assuming lexicographical ordering) to produce candidate \(k\)-itemsets \(C_k\).
  3. Candidate Pruning Step: For each candidate \(c \in C_k\), verify whether all of its \((k-1)\)-subsets are present in \(L_{k-1}\). If any subset is absent, discard \(c\) immediately from \(C_k\).
  4. Database Counting Pass: Scan database \(\mathcal{D}\) to count occurrences of remaining candidates in \(C_k\). Retain those satisfying minimum support to form \(L_k\).
  5. Termination: Repeat steps 2–4 until \(L_k\) is empty. Generate association rules from all frequent itemsets satisfying minimum confidence.

Complete Worked Numerical Example

Database: Consider \(|\mathcal{D}| = 5\) transactions over items \(\{A, B, C, D, E\}\):

T1: {A, B, E}
T2: {B, D}
T3: {B, C}
T4: {A, B, D}
T5: {A, C, E}

Thresholds: \(\text{min\_sup} = 40\% = 2/5\) (minimum count = 2); \(\text{min\_conf} = 70\%\).

Iteration 1 (\(k = 1\)):

  • Candidate 1-itemsets \(C_1\): \(\{A\}: 3, \{B\}: 4, \{C\}: 2, \{D\}: 2, \{E\}: 2\).
  • All meet minimum support count \(\ge 2\). Thus \(L_1 = \{\{A\}, \{B\}, \{C\}, \{D\}, \{E\}\}\).

Iteration 2 (\(k = 2\)):

  • Join \(L_1 \bowtie L_1\) to form \(C_2\): \(\{A,B\}, \{A,C\}, \{A,D\}, \{A,E\}, \{B,C\}, \{B,D\}, \{B,E\}, \{C,D\}, \{C,E\}, \{D,E\}\).
  • Count support from database:
    • \(\{A, B\}\): T1, T4 \(\implies\) count = 2 \(\ge 2\) (Frequent)
    • \(\{A, C\}\): T5 \(\implies\) count = 1 (Infrequent, pruned)
    • \(\{A, D\}\): T4 \(\implies\) count = 1 (Infrequent, pruned)
    • \(\{A, E\}\): T1, T5 \(\implies\) count = 2 \(\ge 2\) (Frequent)
    • \(\{B, C\}\): T3 \(\implies\) count = 1 (Infrequent, pruned)
    • \(\{B, D\}\): T2, T4 \(\implies\) count = 2 \(\ge 2\) (Frequent)
    • \(\{B, E\}\): T1 \(\implies\) count = 1 (Infrequent, pruned)
    • \(\{C, D\}\): None \(\implies\) count = 0 (Pruned)
    • \(\{C, E\}\): T5 \(\implies\) count = 1 (Pruned)
    • \(\{D, E\}\): None \(\implies\) count = 0 (Pruned)
  • Frequent 2-itemsets: \(L_2 = \{\{A, B\}, \{A, E\}, \{B, D\}\}\).

Iteration 3 (\(k = 3\)):

  • Join \(L_2 \bowtie L_2\): Candidate \(\{A, B, E\}\) is generated from \(\{A, B\}\) and \(\{A, E\}\).
  • Pruning Step: Check subsets of \(\{A, B, E\}\): Subsets are \(\{A, B\} \in L_2\), \(\{A, E\} \in L_2\), but \(\{B, E\} \notin L_2\)!
  • Because subset \(\{B, E\}\) is infrequent, candidate \(\{A, B, E\}\) is pruned prior to any database scan.
  • No candidates survive: \(C_3 = \emptyset \implies L_3 = \emptyset\). Algorithm terminates.

Rule Generation Example:

From frequent itemset \(\{A, B\}\) (\(\text{supp} = 2/5 = 0.40\)):

  • Rule \(A \implies B\): \(\text{conf} = \frac{\text{supp}(\{A, B\})}{\text{supp}(\{A\})} = \frac{2}{3} = 66.7\%\) (Below 70%, Rejected).
  • Rule \(B \implies A\): \(\text{conf} = \frac{\text{supp}(\{A, B\})}{\text{supp}(\{B\})} = \frac{2}{4} = 50.0\%\) (Below 70%, Rejected).

From frequent itemset \(\{B, D\}\) (\(\text{supp} = 2/5 = 0.40\)):

  • Rule \(D \implies B\): \(\text{conf} = \frac{\text{supp}(\{B, D\})}{\text{supp}(\{D\})} = \frac{2}{2} = 100\%\) (Meets 70% threshold! Accepted).
  • \(\text{lift}(D \implies B) = \frac{\text{conf}(D \implies B)}{\text{supp}(\{B\})} = \frac{1.0}{4/5} = 1.25 > 1\) (Positive correlation).

3. Handling Large Datasets in Main Memory

The Bottleneck of Standard Apriori

The standard Apriori algorithm requires \(k\) full sequential disk scans (where \(k\) is the length of the maximum frequent itemset). Furthermore, in Iteration 2, the number of candidate pairs is \(|C_2| = \binom{|L_1|}{2}\). If \(|L_1| = 10^5\), \(|C_2| \approx 5 \times 10^9\) pairs, which requires over 20 GB of memory just to store candidate count arrays. To overcome this memory bottleneck, several advanced algorithmic optimizations were developed:

1. The PCY (Park-Chen-Yu) Algorithm

The PCY algorithm observes that during Pass 1, while counting 1-itemsets, significant unused main memory exists. PCY exploits this idle memory by maintaining a hash table of bucket counters:

  1. Pass 1: For each transaction, count individual item frequencies in an array \(A\). Simultaneously, generate all pairs present in the transaction, hash each pair using hash function \(h(i, j)\) to a bucket index in range \([0, B-1]\), and increment that bucket counter: 
    bucket[h(i, j)] += 1
  2. Bitmap Generation: At the end of Pass 1, convert the bucket counters into a compact bitmap: if \(\text{bucket}[k] \ge \text{min\_sup}\), set \(\text{bitmap}[k] = 1\); otherwise set \(\text{bitmap}[k] = 0\). The entire bitmap requires only \(B/8\) bytes of RAM.
  3. Candidate Generation in Pass 2: A pair \(\{i, j\}\) is admitted into candidate set \(C_2\) if and only if:
    • Both individual items are frequent: \(i \in L_1\) and \(j \in L_1\), AND
    • Its hash bucket is frequent: \(\text{bitmap}[h(i, j)] == 1\).

If a bucket count is below minimum support, no pair hashing to that bucket can possibly be frequent. This filters out the vast majority of candidate 2-itemsets before Pass 2 begins.

2. Multistage and Multihash Algorithms

  • Multistage Algorithm: Adds an intermediate pass (Pass 1.5). During Pass 1.5, only pairs whose bucket was frequent in Pass 1 are hashed using a second independent hash function \(h_2\) into a second hash table. In Pass 2, a pair must pass both bitmap filters. This further compresses \(C_2\) at the expense of one extra disk scan.
  • Multihash Algorithm: Uses two or more hash tables simultaneously in Pass 1. A pair is retained only if all corresponding bucket positions in both bitmaps are 1. Requires no extra passes, but partitions available memory across multiple hash tables.

3. Limited Pass Algorithms

Algorithm Number of Passes Core Mechanism Guarantees / Trade-offs
Simple Sampling 1 pass (over sample) + 1 optional pass Draw a random sample \(S\) of the database that fits in RAM. Run Apriori on \(S\) with scaled support threshold \(s' = s \times |S|/|\mathcal{D}|\). Fast, but subject to false positives and false negatives due to sampling variance.
SON Algorithm
(Savasere, Omiecinski, Navathe)		 Exactly 2 Passes Partition database \(\mathcal{D}\) into \(p\) chunks that fit in RAM.
  • Pass 1: Mine local frequent itemsets in each chunk with threshold \(\text{min\_sup} / p\). Take the union of all local frequent sets to form candidate set \(C\). (Monotonicity theorem: any globally frequent itemset must be locally frequent in at least one partition).
  • Pass 2: Stream through full database once to compute exact global counts for candidates in \(C\).
 100% exact (zero false positives, zero false negatives). Ideal for distributed MapReduce and Apache Spark implementations.
Toivonen's Algorithm 1 Pass (with high probability; 2 passes if fail)
  • Mine a sample \(S\) with lower threshold \(s' = 0.8 \times s \times |S|/|\mathcal{D}|\).
  • Construct the Negative Border \(NB(L_S)\): all itemsets that are not frequent in \(S\), but all of their immediate subsets are frequent.
  • Scan full database once: count support of both \(L_S\) and \(NB(L_S)\).
  • If no itemset in \(NB(L_S)\) turns out to be globally frequent, the results are provably exact in a single pass. If any negative border item is frequent, re-run with another pass.
 Deterministic accuracy when successful; failure probability can be made arbitrarily small by tuning sample size and threshold buffer.

4. Counting Frequent Itemsets in a Stream

The Lossy Counting Algorithm (Manku & Rajagopalan, 2002)

Lossy Counting computes all items (or itemsets) whose frequency in an unbounded stream of length \(N\) exceeds support threshold \(s \in (0, 1]\), with an error tolerance parameter \(\epsilon \ll s\), using only \(O(\frac{1}{\epsilon} \log(\epsilon N))\) memory.

Mechanism:

  1. Divide the incoming stream conceptually into buckets of width \(w = \lceil \frac{1}{\epsilon} \rceil\). The first bucket has ID 1, the second ID 2, etc. Current bucket ID is \(b_{\text{current}} = \lceil N / w \rceil\).
  2. Maintain a data structure of entries \((e, f, \Delta)\), where \(e\) is the item/itemset, \(f\) is its estimated frequency, and \(\Delta\) is the maximum possible error in \(f\).
  3. When an item \(e\) arrives:
    • If \(e\) exists in the data structure, increment its count: \(f \leftarrow f + 1\).
    • If \(e\) does not exist, insert a new entry: \((e, 1, b_{\text{current}} - 1)\).
  4. Pruning Step: At the boundary of each bucket (every \(w\) arrivals), prune all entries that satisfy: \[ f + \Delta \le b_{\text{current}} \]
  5. Query Output: When queried for frequent items, output all entries satisfying \(f \ge (s - \epsilon)N\).

Theoretical Guarantees:

  • No False Negatives: All items with true frequency \(f_{\text{true}} \ge sN\) are guaranteed to be output.
  • Bounded False Positives: No item with true frequency \(f_{\text{true}} < (s - \epsilon)N\) is ever output.
  • Underestimation Bound: For any output item, \(f_{\text{true}} - \epsilon N \le f \le f_{\text{true}}\).

5. Clustering Techniques

Definition and Foundations

Clustering is an unsupervised machine learning task that partitions an unlabeled dataset \(X = \{x_1, x_2, \dots, x_n\} \subset \mathbb{R}^d\) into \(k\) discrete groups (clusters) such that intra-cluster similarity is maximized (points within a cluster are as close to each other as possible) and inter-cluster similarity is minimized (points in different clusters are as distant as possible).

Common Distance Metrics

  • Euclidean Distance (\(L_2\) norm): \(d(x, y) = \sqrt{\sum_{i=1}^d (x_i - y_i)^2}\). Standard metric for continuous, geometric Euclidean spaces.
  • Manhattan Distance (\(L_1\) norm): \(d(x, y) = \sum_{i=1}^d |x_i - y_i|\). Robust against outliers; grid-based navigation.
  • Minkowski Distance (\(L_p\) norm): \(d(x, y) = \left(\sum_{i=1}^d |x_i - y_i|^p\right)^{1/p}\). Generalization of \(L_1\) (\(p=1\)) and \(L_2\) (\(p=2\)).
  • Cosine Distance: \(d_{\cos}(x, y) = 1 - \frac{x \cdot y}{\|x\|_2 \|y\|_2}\). Measures orientation rather than magnitude; standard for text documents and high-dimensional sparse TF-IDF vectors.
  • Jaccard Distance: \(d_J(A, B) = 1 - \frac{|A \cap B|}{|A \cup B|}\). Standard for binary sets and categorical transaction overlaps.

6. K-Means Clustering

Mathematical Objective Function

K-Means seeks a partition of \(n\) points into \(k\) disjoint sets \(\{C_1, C_2, \dots, C_k\}\) with corresponding centroids \(\{\mu_1, \mu_2, \dots, \mu_k\}\) that minimizes the Within-Cluster Sum of Squares (WCSS), also called inertia:

\[ J = \sum_{j=1}^k \sum_{x_i \in C_j} \|x_i - \mu_j\|^2 \]

Lloyd's Algorithm (Standard K-Means)

  1. Initialization: Choose \(k\) initial cluster centroids \(\mu_1^{(0)}, \dots, \mu_k^{(0)}\).
  2. Assignment Step: Assign each data point \(x_i\) to the cluster with the closest centroid (Voronoi partition): \[ C_j^{(t)} = \{ x_i : \|x_i - \mu_j^{(t)}\|^2 \le \|x_i - \mu_l^{(t)}\|^2 \quad \forall l, 1 \le l \le k \} \]
  3. Update Step: Recompute each centroid as the geometric mean of all points assigned to it: \[ \mu_j^{(t+1)} = \frac{1}{|C_j^{(t)}|} \sum_{x_i \in C_j^{(t)}} x_i \]
  4. Convergence: Repeat steps 2 and 3 until centroids stabilize (\(\|\mu_j^{(t+1)} - \mu_j^{(t)}\| < \epsilon\)) or assignments no longer change. Guaranteed to converge to a local optimum in a finite number of iterations because \(J\) strictly decreases at each step.

Figure 2: K-Means clustering convergence (k=3). Ringed crosses indicate final converged cluster centroids. Dashed lines illustrate the Voronoi partition boundaries separating cluster regions.

K-Means++ Smart Initialization

Standard random initialization often converges to poor local minima if two centroids are placed in the same natural cluster. K-Means++ (Arthur & Vassilvitskii, 2007) initializes centroids with a dispersion probability guarantee:

  1. Choose the first centroid \(\mu_1\) uniformly at random from dataset \(X\).
  2. For each data point \(x\), compute \(D(x)\), the shortest distance from \(x\) to the closest existing centroid.
  3. Choose the next centroid \(\mu_j\) from \(X\) with probability proportional to the squared distance: \[ P(x \text{ is chosen}) = \frac{D(x)^2}{\sum_{x' \in X} D(x')^2} \]
  4. Repeat steps 2 and 3 until \(k\) centroids are chosen. Guarantees an expected solution bound of \(O(\log k)\) times the optimal WCSS.

Selecting the Optimal Value of \(k\)

  • The Elbow Method: Plot WCSS (\(J\)) against increasing values of \(k\) (\(k = 1, 2, \dots\)). As \(k\) increases, \(J\) decreases monotonically. The optimal \(k\) is the point of inflection ("elbow") where adding more clusters yields diminishing reductions in variance.
  • Silhouette Coefficient: For each point \(i\), compute intra-cluster distance \(a(i)\) (average distance to all other points in the same cluster) and nearest-cluster distance \(b(i)\) (average distance to points in the closest neighboring cluster): \[ s(i) = \frac{b(i) - a(i)}{\max(a(i), b(i))} \] \(s(i) \in [-1, +1]\). A mean silhouette score near \(+1.0\) indicates well-separated, cohesive clusters; values near \(0\) indicate overlapping clusters; negative values indicate misclassification.

7. Hierarchical Clustering

Agglomerative vs. Divisive Strategies

Hierarchical clustering constructs an entire hierarchy of nested clusters represented as a binary tree called a dendrogram. It requires no prior specification of \(k\):

  • Agglomerative (Bottom-Up): Starts with \(n\) singleton clusters. At each iteration, the two most similar (least distant) clusters are merged. Continues until all points belong to a single root cluster. Computational complexity is \(O(n^2 \log n)\) or \(O(n^3)\).
  • Divisive (Top-Down): Starts with all data points in a single mega-cluster. Recursively splits clusters using a flat clustering method (such as 2-means) until each point is an isolated singleton.

Linkage Criteria (Distance between Clusters \(A\) and \(B\))

Linkage Metric Formula Behavior & Properties
Single Linkage
(Nearest Neighbor)		 \(D(A, B) = \min_{x \in A, y \in B} d(x, y)\) Can extract arbitrary non-elliptical shapes; vulnerable to the chaining effect (elongated, straggly clusters connected by thin noise bridges).
Complete Linkage
(Farthest Neighbor)		 \(D(A, B) = \max_{x \in A, y \in B} d(x, y)\) Produces compact, spherical clusters of roughly equal diameter; sensitive to outliers.
Average Linkage
(UPGMA)		 \(D(A, B) = \frac{1}{|A||B|} \sum_{x \in A} \sum_{y \in B} d(x, y)\) Intermediate behavior; compromises between single and complete linkage; robust to moderate noise.
Ward's Minimum Variance \(\Delta \text{ESS}_{AB} = \frac{|A||B|}{|A| + |B|} \|\mu_A - \mu_B\|^2\) Merges the two clusters whose union minimizes the increase in total within-cluster sum of squares. Yields dense, well-balanced spherical clusters.

8. Clustering High-Dimensional Data: CLIQUE and ProCLUS

The Curse of Dimensionality in Clustering

As feature dimensionality \(d\) increases into dozens or hundreds of dimensions, traditional clustering algorithms break down due to two geometric phenomena:

  1. Distance Concentration: The difference between the distance to the nearest neighbor and the distance to the farthest neighbor vanishes relative to the distance itself: \[ \lim_{d \to \infty} \frac{d_{\max} - d_{\min}}{d_{\min}} = 0 \] Every point appears equidistant from every other point, rendering distance-based partitioning meaningless.
  2. Irrelevant Subspace Dimensions: In high-dimensional datasets (e.g., genomics, customer telemetry), clusters typically exist only in specific lower-dimensional projections (subspaces). In the remaining dimensions, points are distributed randomly like background noise, which completely obscures natural clusters when computing full-dimensional distances.

CLIQUE (CLustering In QUEst)

CLIQUE (Agrawal et al., 1998) is a grid-based, density-based subspace clustering algorithm. It automatically finds dense clusters embedded in any subspace of the original feature space.

Key Concepts and Apriori Property:

  • Grid Discretization: Partition each dimension into \(\xi\) equal-width intervals. The intersection of intervals across any \(k\) dimensions forms a \(k\)-dimensional rectangular grid cell (unit).
  • Dense Unit: A cell is defined as dense if the fraction of total dataset points falling inside it exceeds a user-defined density threshold parameter \(\tau\).
  • Apriori Subspace Pruning Property: If a \(k\)-dimensional cell is dense, all of its \((k-1)\)-dimensional projection cells must also be dense. Conversely, if any \((k-1)\)-dimensional projection is not dense, the \(k\)-dimensional cell cannot be dense.

Algorithm Steps:

  1. Find all 1-dimensional dense units by scanning each attribute independently.
  2. Iteratively generate candidate \(k\)-dimensional units from pairs of \((k-1)\)-dimensional dense units sharing \((k-2)\) common dimensions, pruning candidates with non-dense sub-projections (Apriori principle).
  3. Scan dataset to identify dense \(k\)-dimensional units.
  4. For each subspace containing dense units, connect adjacent dense units to form connected components (clusters).
  5. Generate minimal Disjunctive Normal Form (DNF) symbolic descriptions (bounding boxes) for each discovered cluster.

Figure 4: CLIQUE Subspace Clustering. Grid cells with point density exceeding threshold \tau are classified as dense units. Connected adjacent dense units form a subspace cluster, enabling detection of arbitrary shapes regardless of data distribution in unrelated dimensions.

ProCLUS (Projected Clustering)

While CLIQUE is grid-based, ProCLUS (Aggarwal et al., 1999) is a medoid-based projected clustering algorithm. It discovers clusters where each cluster \(C_i\) is associated with its own distinct subset of relevant dimensions \(\mathcal{D}_i \subset \{1, \dots, d\}\) (having average subspace cardinality \(l \ll d\)):

  • Initialization Phase: Selects a well-scattered set of \(k\) medoid candidates using greedy distance-based sampling.
  • Iterative Phase:
    1. For each current medoid \(m_i\), evaluate the variance (standard deviation) of points along every dimension. Dimensions with low intra-cluster variance \(\sigma_{ij}^2\) are assigned to \(\mathcal{D}_i\).
    2. Assign each data point to its closest medoid using Manhattan distance computed only over that cluster's relevant subspace dimensions: \[ d(x, m_i) = \frac{1}{|\mathcal{D}_i|} \sum_{j \in \mathcal{D}_i} |x_j - m_{i, j}| \]
    3. Evaluate clustering quality using total objective function. Bad medoids (those with small cluster size or high variance) are swapped with random candidate medoids.
  • Refinement Phase: Computes one final pass over data to clean noise and optimize cluster boundaries.

9. Clustering in Non-Euclidean Space: BFR & CURE

The BFR (Bradley-Fayyad-Reina) Algorithm

BFR (1998) scales K-Means to massive disk-resident datasets by assuming clusters are normally distributed around centroids in Euclidean space. Points are summarized into three in-memory memory sets:

  1. Discard Set (DS): Points that are sufficiently close to a cluster centroid (measured via Mahalanobis distance \(< 3\sigma\)). Points are discarded from memory immediately after updating the cluster's sufficient statistics:
    • \(N\): number of points.
    • \(\vec{SUM} = \sum x_i\): vector sum of coordinates along each dimension.
    • \(\vec{SUMSQ} = \sum x_i^2\): vector sum of squared coordinates.
    Centroid \(\mu = \vec{SUM}/N\) and variance \(\sigma^2 = (\vec{SUMSQ}/N) - \mu^2\) are calculated on-the-fly.
  2. Compression Set (CS): Mini-clusters of points that are close to each other but not close enough to any existing cluster centroid. Stored using the same \((N, \vec{SUM}, \vec{SUMSQ})\) summary.
  3. Retained Set (RS): True outlier points that cannot be assigned to any DS or CS. Kept in raw form in RAM until subsequent batches arrive.

The CURE (Clustering Using REpresentatives) Algorithm

Standard K-Means fails on non-spherical clusters (e.g., crescents, interlocking spirals), while hierarchical single linkage is vulnerable to noise chaining. CURE (Guha, Rastogi, Shim, 1998) provides a hybrid solution:

  • Instead of using a single centroid or all points, CURE represents each cluster by a fixed number \(c\) of well-scattered representative points.
  • Shrinkage Mechanism: The \(c\) representative points are shrunk towards the cluster center of mass by a fraction \(\alpha \in [0, 1]\) (typically \(\alpha = 0.2\)): \[ p_{\text{shrunk}} = p + \alpha (\mu - p) \] Shrinkage dampens the adverse effect of isolated outlier points and noise spikes while preserving the non-spherical geometric geometry of the cluster.
  • Cluster distance is defined as the minimum Euclidean distance between any pair of shrunk representative points: \[ D_{\text{CURE}}(C_1, C_2) = \min_{p \in \text{Rep}(C_1), q \in \text{Rep}(C_2)} \|p - q\| \]
  • Handles arbitrary geometric shapes, complex non-convex boundaries, and scales to large datasets using random sampling and spatial partitioning (KD-trees).

10. Clustering for Streams and Parallelism

Stream Clustering: CluStream

Traditional clustering algorithms require multiple passes over the dataset. Over an unbounded stream, multi-pass algorithms are impossible. The CluStream algorithm (Aggarwal et al., 2003) introduces a two-phase stream clustering architecture:

  1. Online Micro-Clustering Phase:
    • Maintains \(q\) statistical micro-clusters in real-time memory (where \(q \gg k\)).
    • Each micro-cluster is stored as a Cluster Feature (CF) tuple containing: \((N, \vec{LS}, \vec{SS}, \text{LST}, \text{SST})\), where \(N\) is point count, \(\vec{LS}\) is linear sum of points, \(\vec{SS}\) is sum of squares, \(\text{LST}\) is linear sum of timestamps, and \(\text{SST}\) is sum of squared timestamps.
    • When a new stream point arrives, it is absorbed into its nearest micro-cluster if within maximum boundary distance; otherwise, a new micro-cluster is initialized and the oldest inactive micro-cluster is merged or evicted. Operation takes \(O(1)\) time.
  2. Offline Macro-Clustering Phase:
    • Operates on-demand when an analyst submits a query for time horizon \(h\).
    • Extracts the difference between current micro-clusters and historical snapshot micro-clusters stored \(h\) time units ago (exploiting the additive property of CF vectors).
    • Executes a modified weighted K-Means on the extracted micro-clusters to output the final \(k\) macro-clusters.

Parallel and Distributed Clustering (MapReduce / Spark)

For petabyte-scale datasets, clustering is parallelized across compute clusters:

  • Distributed K-Means on MapReduce:
    • Map Phase: Each mapper reads a shard of the dataset and current broadcast centroids. For every point, it finds the nearest centroid and outputs \((j, (x_i, 1))\), where \(j\) is the centroid index.
    • Combine Phase: Locally aggregates points per centroid into local vector sum and count.
    • Reduce Phase: Aggregates sums and counts from all mappers, divides \(\sum x_i / \sum 1\) to compute new global centroids, and tests for convergence.
  • Apache Spark MLLib: Caches data partitions in distributed cluster RAM (Resilient Distributed Datasets / DataFrames), eliminating MapReduce disk I/O bottlenecks and executing iterative K-Means 20–50x faster.
